## 判断题 (10 分)

1. **模型-视图-控制器（MVC）只作为软件开发中的系统架构使用。**
   **答案：错误**
   **解析：** 第五课“模型-视图-控制器（MVC）”部分提到：“术语‘MVC’用于表示多种略有不同的含义：系统架构（系统设计）、设计模式（程序设计）、程序开发框架”，说明MVC不仅仅是系统架构，也包括程序设计模式和开发框架。

2. **可访问性需求只与残障用户相关，不影响软件整体设计。**
   **答案：错误**
   **解析：** 第五课“可访问性需求”中指出：“软件设计者必须为残障用户做好准备……您可能需要承担支持残障人士的法律责任。” 此外，辅助功能往往出现在用户界面中，影响整体设计。

3. **在UML中，聚合意味着子对象不能独立于父对象存在。**
   **答案：错误**
   **解析：** 第六课“UML中的基本关系”部分明确指出：“聚合意味着子对象可以独立于父对象存在。例子：班级和学生，删除班级，学生仍然存在”。

4. **UML中的包是逻辑相关的UML元素的集合。**
   **答案：正确**
   **解析：** 第六课“包图”部分提到，“包是逻辑相关的UML元素的集合。”。

5. **软件建模可以促进开发者之间的沟通与协作。**
   **答案：正确**
   **解析：** 第六课“系统架构模型”部分强调：“选择最能建模系统并对所有人来说最清晰的模型”，其目的之一就是促进理解与协作。

6. **使用UML的目的之一是提供全面的文档。**
   **答案：正确**
   **解析：** 第六课“系统架构模型”中提到：“每个模型都必须有一个图表和一个支持规范”，说明UML用于文档化系统结构和设计。

7. **组件图是行为图的一种。**
   **答案：错误**
   **解析：** 第六课“结构图”和“组件图”部分提到，组件图属于结构图，而非行为图。行为图包括活动图、用例图、状态图等。

8. **在部署图中，节点是运行时存在的物理元素，提供计算资源。**
   **答案：正确**
   **解析：** 第六课“部署图”部分明确指出，“节点是在运行时存在的物理元素，提供计算资源，例如计算机、智能手机、路由器”等。

9. **在系统设计阶段，子系统应高耦合。**
   **答案：错误**
   **解析：** 第六课“子系统”部分明确说明，“将复杂系统理想地划分为子系统，子系统之间的耦合性较低，子系统内部的内聚性较高”。

10. **“存储库”架构通过共享代码解耦系统。**
    **答案：错误**
    **解析：** 第六课“架构风格：存储库”指出：“劣势：修改存储库很困难，因为所有其他组件都与其耦合。” 这说明存储库架构不是通过共享代码实现解耦，反而存在耦合问题。

## 简答题 (10 分)

1. 请简要说明“聚合”（Aggregation）与“组合”（Composition）之间的区别。（2 分）

**答案：**  

   * 聚合表示“整体-部分”的关系，但子对象可以在父对象之外独立存在。  
   * 例如：“班级”聚合“学生”，即使班级被删除，学生仍然存在。  
   * 而组合表示更强的“整体-部分”关系，子对象不能独立存在。  
   * 例如：“房屋”组合“房间”，房间离开房屋将无法存在。  

（出处：第六课“UML中的基本关系”部分，解释了聚合和组合的区别）

2. 从系统设计的角度看，软件系统通常采用特定的架构风格，如“客户端/服务器”。请描述一个使用 C/S 架构的示例。（2 分）

**答案：**  
   一个经典的客户端/服务器（C/S）架构示例是 **QQ 桌面版**。  
   在该架构中：  

   - **客户端（Client）** 是安装在用户本地计算机上的 QQ 程序，提供图形用户界面，处理用户输入、消息发送、联系人管理等功能。  

   - **服务器（Server）** 是腾讯部署在数据中心的后台系统，负责用户身份验证、消息中转、好友信息同步、离线消息存储等服务。  

   客户端与服务器通过专用协议建立稳定的长连接，实现即时通信。这种架构适合需要实时性强、交互频繁的应用。  

（出处：第六课“架构风格：客户端/服务器”中提到，客户端和服务器之间使用协议通信，并控制流彼此独立，是 C/S 模型的关键特征）


3. MVC 架构包括三个层次。请解释每个层的作用，并说明 MVC 架构的优点。（2 分）

**答案：**  

   - Model（模型）：负责应用的数据、业务逻辑、内容管理。  

   - View（视图）：负责界面展示，即用户界面。  

   - Controller（控制器）：负责导航和用户输入处理。  

     **MVC 优点：** 将数据、视图与控制逻辑分离，便于维护和扩展，支持复用不同的视图组件。 

（出处：第五课“模型-视图-控制器（MVC）”部分详细讲解了三层的角色及其分离的优势）


4. 请描述一个云服务中的安全风险，以及相应的缓解方案。（2 分）

**答案：**  
   **风险：** 数据泄露是云服务中常见的安全风险之一。  
   **缓解方案：** 使用数据加密技术对存储和传输过程中的数据进行保护，结合身份验证机制（如双因素认证）来防止未授权访问。  

（出处：第七课“安全技术：加密”、“风险管理”、“系统架构”部分均涉及该类风险及对策）

5. 请简要说明“微服务”（microservices）架构。（2 分）

**答案：**  
   微服务架构是将系统划分为多个独立部署、可替换的服务组件，每个服务通过标准接口（如 REST API）提供功能。每个服务可以独立开发、测试和部署，从而提高系统的可维护性和扩展性。  

（出处：第六课“微服务”部分指出：“组件封装服务并通过标准接口（如 REST）公开它们”，强调其独立性与低耦合）
